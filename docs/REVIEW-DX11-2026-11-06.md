## 1. 必修

### R-1 光流描述符被同阶段后续 draw 覆盖

- **位置：** `src/nr/dense_flow.cpp:313-315`、`:323`
- **现象：** SRV 表按 `stage * 7` 定位，每个阶段只有一张 7 槽的表。同一阶段的多次 draw 共用这张表：
  - DepthMip 3 次
  - Down 7 次
  - Match 8 次
  - Pool 7 次
  - Upscale 2 次
- **后果：** 根签名 1.0 下，描述符在 GPU 执行时才被读取，所以同阶段所有 draw 读到的都是最后一次写入的内容。例如 8 次 Match 都会读到 level 0 的金字塔。整条原生 MV 金字塔是错的，模型拿到错误运动向量，会出现拖影或闪烁。
- **附带：** `srvSource[stage][n]` 缓存每次都会被同阶段下一次 draw 改掉，实际起不到缓存作用。
- **修法：**
  - 按 draw 序号分配槽位（共 29 次 × 7 = 203 个），heap 改为这个大小。
  - 缓存键改为 draw 序号。
  - RTV 在 `OMSetRenderTargets` 时就被读取，可以继续按阶段复用。
- **对照：** `src/nr/preview.cpp` 的改动已经正确地按 tile 分配了独立的 (SRV, UAV) 对，可以照着改。

### R-2 面板隐藏时 WM_INPUT 不再交给游戏

- **位置：** `src/ui/panel.cpp:139-146`
- **现象：** 面板隐藏且非热键时，直接 `return DefWindowProcW(...)`，跳过了 `route->original`。
- **后果：** 依赖 `WM_INPUT` 的游戏会失去鼠标视角和 raw 键盘输入，FPS 类游戏基本无法操作。
- **修法：** 锁外只做热键判断。非热键消息继续走后面的原路径，最终调用 `CallWindowProcW(old, …)`。NR 现在已经不持锁，原路径不会再被一帧的 GPU 工作卡住，所以提前返回没有必要。

### R-3 Resize 时死锁

- **位置：** `src/nr/depth11.cpp:109-122`、`:294`、`:698`；触发点 `src/ui/panel.cpp:453`（`ReleaseNativeCapture`）、`:466`（`depth::Register`）
- **触发链：**
  1. `BeforeResize` → `depth::Release(device)`：只从表里删掉 context，native context 上的旧 cookie 仍在，`published` 仍为 true。
  2. `AfterResize` → `Register` → 在 `RegisterLocked` 中持有独占 `R().mutex`，执行 `SetPrivateDataInterface`，替换旧 cookie。
  3. 旧 cookie 引用归零 → `ContextLifetime::Release` → 在同一线程再次请求 `unique_lock(R().mutex)`。
  4. `std::shared_mutex` 不可重入 → 死锁，游戏卡在 `ResizeBuffers`。
- **条件：** `NativeCapture=1` 且面板处于捕获状态时，每次 Resize 都会触发。
- **修法（二选一）：**
  - `Release(device)` 删除表项时，把对应 lifetime 的 `published` 置为 false。该字段要改成 `std::atomic<bool>`。
  - 把 `SetPrivateDataInterface` 移到独占锁外完成。

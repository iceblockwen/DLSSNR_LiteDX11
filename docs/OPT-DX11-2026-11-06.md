# DLSSNR_LiteDX11 优化报告 — 2026-11-06

**基线：** `f58df45`（去冗余复查：删只写不读字段、无用接口、未用 include）
**范围：** `src/` 全部 C++/HLSL、`CMakeLists.txt`、`DLSSNR_LiteDX11.ini`
**方法：** 逐文件静态通读 + 符号引用核对 + fxc `/O3` 统计 shader 指令数（临时文件已删）
**限制：** 本报告不改代码。未运行游戏、未做 GPU trace。文中次数按代码推算，纹理操作数是 4K 下的估算，**都不是毫秒**。

## 总判断

- 工程已经过多轮瘦身，纯 CPU 微优化的剩余收益很小，估计每帧在百微秒级。
- 卡顿根因大概率在 **GPU 忙跳帧、锁、重建** 三处。
- GPU 帧时间的最大杠杆在光流的上采样链。模型本身不在可优化范围内。

## 1. P0 卡顿根因

| # | 问题 | 位置 | 建议 |

## 2. P1 GPU 成本

光流每帧 29 个 draw：Prepare 1 + DepthMip 3 + Down 7 + Match 8 + Pool 7 + Upscale 2 + Finish 1。4K 纹理操作估算：

| Pass | 纹理操作 | 占比 | fxc 指令数 |
|---|---|---|---|
| Match | ≤115M（最坏情况，实际有早退） | ≤31% | 704 |
| **Finish（全分辨率）** | 83M | 22% | 92 |
| **Upscale 1/2** | 54M | 15% | 96 |
| **Down** | 50M | 13% | 63 |
| Upscale 1/4 | 26M | 7% | 96 |
| Pool | 22M | 6% | 111 |
| Prepare | 17M | 4.5% | 60 |

其余 shader 指令数：`lite_color` 265、`lite_preview` 93、`lite_meter` 53、`bridge_convert:Depth` 15、`PSDepthMip` 5。

| # | 优化 | 位置 | 收益 | 风险 |
|---|---|---|---|---|
| 1 | **previous 金字塔改指针交换。** 现在每帧重算 previous 各级，结果与上一帧 current 逐值相同（同权重、同格式）。Down 从双 RT 变单 RT，并删除帧尾两次拷贝。 | `src/nr/dense_flow.cpp:418`、`:433-434`；`src/nr/shaders/dense_flow.hlsl:312-334`、`:359-361` | −25M 采样，−1 次 16.6 MB 全屏拷贝，画质不变 | 低。历史重置时须清空全部 8 级 |
| 2 | **SDR/原生路径跳过 proxy。** 原生路径 `sceneLinear` 恒为假，此时 proxy 只是 RGBA8→RGBA16F 的恒等拷贝。 | `src/nr/capture11.cpp:767`；`src/nr/pass.cpp:841`；`src/nr/shaders/lite_color.hlsl:83` | −1 次全屏 CS，−66 MB 写入与显存 | 需 A/B，确认模型接受 RGBA8 输入 |

## 5. 构建（改动最小）

`CMakeLists.txt` 目前没有开 LTCG。可以：

- 开 `CMAKE_INTERPROCEDURAL_OPTIMIZATION_RELEASE`，并加 `/Gy /Gw`。
- ImGui 定义 `IMGUI_DISABLE_DEBUG_TOOLS`、`IMGUI_DISABLE_DEMO_WINDOWS`。

这几项会减小 DLL 体积，并允许跨文件内联 `Transition`、`ViewFormat` 这类小函数。具体收益需实测。

## 6. 顺带发现的 bug

1. **深度 SRV 过期（可确认）。** 同描述的新深度纹理通过 `Matches` 后只更新 `twin.source`，直连的 `twin.view` 仍指向旧纹理，模型会一直吃旧深度。修法：source 变化时重建 SRV。位置：`src/nr/bridge.cpp:376`、`:477-481`、`:500`。
2. **深度直连 SRV 可能被清空（需实测）。** 游戏在 Present 时若仍绑定该 DSV，D3D11 会把冲突的 SRV 强制置空，深度读成 0。位置：`src/nr/bridge.cpp:376`、`:503`。
3. **白点重复计算。** `Resolve` 每帧算两次，第一次 `dt=0`（旧报告 LG-5）。位置：`src/nr/pass.cpp:586`、`:654`。
4. **dt 精度不足。** `GetTickCount64` 约 15.6 ms 粒度，Measured 模式下白点滤波会抖。位置：`src/nr/pass.cpp:533`。
